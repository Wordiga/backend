## Wordiga 구현 체크리스트

### 상태 기준

- `Done`: 현재 요구사항에 필요한 구현이 완료되었습니다.
- `In Progress`: 일부 구현되어 있으나 추가 작업이 필요합니다.
- `Todo`: 구현을 시작하지 않았거나 기반 코드만 존재합니다.

  - 현재: Google/Kakao OIDC 사용자 저장과 JWT 발급이 구현되어 있습니다.
  - 후속: 토큰을 URL query parameter로 전달하지 않는 방식으로 변경해야 합니다.

- [x] JWT 인증 필터
  - 현재: Bearer JWT 검증과 회원 ID 인증 객체 생성이 구현되어 있습니다.
  - 후속: 인증 실패 공통 응답과 테스트가 필요합니다.

- [x] 공개·인증 경로 설정
  - 현재: 관광 콘텐츠 목록·상세, health, Swagger 경로는 공개하고 위시·일정 경로는 인증을 요구합니다.

- [x] CORS
  - 현재: 프론트엔드 origin에서 `GET`, `POST`, `PUT`, `PATCH`, `DELETE` 요청을 허용합니다.

- [x] 관광 콘텐츠 목록
  - 현재: 인기·계절 수요 기반 정렬, 키워드·관광타입·시군구 필터와 페이지 응답을 제공합니다.
  - 현재: 계절 추천은 방문 예정 월의 전년도 동월 관광 수요를 사용합니다.

- [x] 콘텐츠 타입별 상세 필드
  - 현재: 관광지·문화시설·행사·여행코스·레포츠·숙박·쇼핑·음식점 소개정보를 공개 DTO로 변환합니다.
  - 현재: 일반 반복정보, 여행코스와 숙박 객실·이미지를 lowerCamelCase DTO로 변환합니다.

- [x] 위시 등록
  - 현재: `contentId`만 받고 서버가 관광공사 상세정보를 조회하여 저장합니다.
  - 현재: 충청남도 시군구별 자동 분류와 `mapx`, `mapy` 저장이 구현되어 있습니다.
  - 후속: 통합 관광 콘텐츠 서비스로 상세 조회 책임을 이동하고 외부 API 실패 테스트를 추가해야 합니다.

- [x] 위시 삭제
  - 현재: 회원 ID와 콘텐츠 ID로 삭제합니다.
  - 후속: 존재하지 않는 위시 삭제의 응답 정책을 확정해야 합니다.

- [x] 위시 지역 폴더
  - 현재: 시군구별 집계와 폴더별 최신순 조회가 구현되어 있습니다.
  - 후속: 화면에서 폴더 썸네일이 필요한지 확인해야 합니다.
